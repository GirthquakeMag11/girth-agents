# Memory and experience-reuse in LLM agents — the scholarship

**Question:** We are designing a "lesson learned once" recall layer for an
engine of helper agents doing repeated work: when one agent learns a lesson, it
is recorded once, and every later agent retrieves it instead of re-learning it.
What is the established theory and empirical record on agent memory — its
taxonomy, its experience-reuse mechanisms, its failure modes, its
de-duplication/learn-once behavior, and where humans belong in the loop —
before we build?

**Date:** 2026-10-26. Researched against primary sources: arXiv papers
(and their ACL/NeurIPS/ICLR/AAAI/TMLR proceedings versions where they exist)
plus first-party framework docs (Anthropic, OpenAI, Letta/MemGPT, Mem0).

**Citation style:** Author (year), *Title*, venue — with the clause quoted
where a claim is specific — plus arXiv ID/DOI or URL. Passage numbers are
quoted only where a doc is paginated/sectioned.

## 1. Memory taxonomies in LLM agents

The reference taxonomy comes from CoALA, which imports the cognitive-psychology
division (working / episodic / semantic / procedural) verbatim from classical
cognitive architectures and re-states it for language agents.

- **Working memory is the bounded "now" of the agent, persisting across LLM
  calls.** CoALA: "Working memory maintains active and readily available
  information as symbolic variables for the current decision cycle … This
  includes perceptual inputs, active knowledge (generated by reasoning or
  retrieved from long-term memory), and other core information carried over
  from the previous decision cycle (e.g., agent's active goals)." Crucially it
  is "a data structure that persists across LLM calls," not just the LLM's own
  context: "On each LLM call, the LLM input is synthesized from a subset of
  working memory … The LLM output is then parsed back into other variables"
  (Sumers, Yao, Narasimhan & Griffiths, "Cognitive Architectures for Language
  Agents (CoALA)", *TMLR* 2024, §4.1; arXiv:2309.02427).
- **Episodic memory stores experience, not abstractions.** CoALA: "Episodic
  memory stores experience from earlier decision cycles. This can consist of
  training input-output pairs … history event flows … game trajectories from
  previous episodes … or other representations of the agent's experiences."
  Episodes "may be retrieved into working memory to support reasoning," and the
  agent "can also write new experiences from working to episodic memory as a
  form of learning" (CoALA, §4.1).
- **Semantic memory stores facts about the world and the agent.** CoALA:
  "Semantic memory stores an agent's knowledge about the world and itself."
  Read-only instantiations are RAG and "reading-to-learn" RL, but "language
  agents may also write new knowledge obtained from LLM reasoning into semantic
  memory as a form of learning … to incrementally build up world knowledge from
  experience" (CoALA, §4.1). CoALA re-classifies Reflexion's stored reflections
  exactly this way: an LLM "reflect[s] on failed episodes and store[s] the
  results … as semantic knowledge to be attached to LLM context" (§4.5) — i.e.,
  self-reflections are semantic memory, not episodic, in CoALA's terms.
- **Procedural memory is "how to act," and it lives in two places.** CoALA:
  "Language agents contain two forms of procedural memory: implicit knowledge
  stored in the LLM weights, and explicit knowledge written in the agent's
  code." It is the only store that must be bootstrapped ("must be initialized
  by the designer"), and writing to it is flagged as the riskiest learning
  action: "learning new actions by writing to procedural memory … is
  significantly riskier than writing to episodic or semantic memory, as it can
  easily introduce bugs or allow an agent to subvert its designers'
  intentions" (CoALA, §4.1).
- **Retrieval and learning are the two memory operations.** Retrieval "reads
  information from long-term memories into working memory," implemented as
  "rule-based, sparse, or dense retrieval"; learning is the inverse — "Learning
  occurs by writing information to long-term memory" (CoALA, §4.3, §4.5).
  CoALA notes both gaps that matter for a recall layer: "adaptive and
  context-specific recall remains understudied," and "modifying and deleting
  (a case of 'unlearning') are understudied" (§4.3, §4.5).
- **A survey formalizes the same loop as write–manage–read.** "We formalize
  agent memory as a write–manage–read loop within a POMDP-style agent cycle,"
  with the write/manage operator `U` "not a simple append operation": "In a
  well-designed system it summarizes, deduplicates, scores priority, resolves
  contradictions, and—when appropriate—deletes" ("Memory for Autonomous LLM
  Agents: Mechanisms, Evaluation, and Emerging Frontiers," arXiv:2603.07670,
  §2).
- **MemGPT/Letta gives the OS-inspired hierarchy, not the cognitive one.**
  MemGPT "delineates between two primary memory types: **main context**
  (analogous to main memory/physical memory/RAM) and **external context**
  (analogous to disk memory/disk storage)," paging information between them via
  function calls — "virtual context management" (Packer, Wooders, Lin, Fang,
  Patil, Stoica & Gonzalez, "MemGPT: Towards LLMs as Operating Systems,"
  arXiv:2310.08560, §3). Main context holds editable core-memory blocks
  (persona and human); external context holds recall storage (full history,
  vector-indexed) and archival storage. The agent *self-edits*: it "retrieve[s]
  relevant historical data missing from what is placed in-context, and also
  evict[s] less relevant data from context" (MemGPT, §1). Letta carries this
  forward as an explicit "context hierarchy": the context window ("what the
  model sees on each inference cycle") vs. external context ("everything else
  the Letta agent can access through taking action"), where "Learning is
  achieved through managing context" (Letta, "Context Constitution,"
  https://www.letta.com/constitution/; also "Understanding memory management,"
  https://docs.letta.com/advanced/memory-management).

**Taxonomy takeaway:** one store per *kind* of thing — raw episodes, distilled
facts, reusable procedures — with a sharply bounded working set. A "lesson"
recall layer is, in CoALA's terms, semantic memory that agents write to via a
learning action and read from via a retrieval action.

## 2. Experience reuse and self-improvement

The store-and-retrieve family of methods. For each: what is stored, how it is
retrieved, reported effect.

### Reflexion — verbal self-feedback in an external buffer

- **Stored:** natural-language self-reflections written after each trial by a
  "Self-Reflection" LLM, conditioned on the trajectory and the outcome (binary
  or scalar reward). The feedback "acts as a 'semantic' gradient signal" —
  verbal reinforcement "not by updating weights, but instead through linguistic
  feedback." Short-term memory = current trajectory; long-term memory =
  accumulated reflections (Shinn, Cassano, Berman, Gopinath, Narasimhan & Yao,
  "Reflexion: Language Agents with Verbal Reinforcement Learning," *NeurIPS*
  2023, arXiv:2303.11366, §1, §3).
- **Retrieval:** brute — "we bound mem by a maximum number of stored
  experiences, Ω (usually set to 1–3) to adhere to max context LLM
  limitations," a sliding window that the Actor always sees (Reflexion, §4).
- **Effect:** 91% pass@1 on HumanEval vs. GPT-4's 80%, with significant gains
  on decision-making, coding, and reasoning tasks (Reflexion, abstract).

### Voyager — a skill library as procedural memory

- **Stored:** "an ever-growing skill library of executable code" — each skill
  is a verified, reusable program with an embedding of its description. Skills
  are only committed after an iterative prompting loop runs them through
  environment feedback, execution errors, and self-verification (Wang, Xie,
  Jiang, Mandlekar, Xiao, Zhu, Fan & Anandkumar, "Voyager: An Open-Ended
  Embodied Agent with Large Language Models," arXiv:2305.16291, abstract, §3).
- **Retrieval:** dense retrieval — the current task description is embedded and
  matched against skill-description embeddings; the top skills are retrieved
  and composed (cast as "retrieving grounding procedures from a procedural
  memory" in CoALA, §4.3).
- **Effect:** 3.3× more unique items attained, unlocks tech-tree milestones up
  to 15.3× faster than prior SOTA, and critically "able to utilize the learned
  skill library in a new Minecraft world to solve novel tasks from scratch,
  while other techniques struggle to generalize" (Voyager, abstract). That
  transfer claim is the closest published evidence that a *once*-learned
  procedure library pays off across repeated, similar future tasks.

### ExpeL — insights extracted from a pool of trajectories

- **Stored:** two things — (a) an experience pool of raw successful/failed
  trajectories, and (b) a set of cross-task "insights" (natural-language rules)
  distilled from them. Extraction compares fail vs. success trajectories for
  the same task and finds patterns across successful trajectories of different
  tasks (Zhao, Huang, Xu, Lin, Liu & Huang, "ExpeL: LLM Agents Are Experiential
  Learners," *AAAI* 2024, arXiv:2308.10144, abstract, §4).
- **Retrieval & maintenance:** at inference, top-k successful trajectories
  most similar to the task are retrieved (Faiss kNN, all-mpnet-base-v2), and
  insights are attached to instructions. Insights have an *importance count*:
  ADD starts at 2; UPVOTE/EDIT increment; DOWNVOTE decrements; at zero the
  insight is removed — "This particular design choice robustifies the process
  since even successful trajectories can be suboptimal and mislead the
  generated insights" (ExpeL, §4).
- **Effect:** "consistent enhancement in its performance as it accumulates
  experiences," plus observed cross-task transfer of the distilled insights
  (ExpeL, abstract, §5). Note this is the *opposite* of Reflexion's per-task
  buffer: ExpeL intentionally generalizes lessons across tasks.

### Generative Agents — retrieval-weighted episodic stream + reflection

- **Stored:** a "memory stream" of timestamped natural-language observations,
  and — periodically — "reflections": higher-level, synthesized insights
  (e.g., abstractions about a person's character) written back into the stream
  with higher retrieval priority (Park, O'Brien, Cai, Morris, Liang &
  Bernstein, "Generative Agents: Interactive Simulacra of Human Behavior,"
  *UIST* 2023, arXiv:2304.03442, §3-4).
- **Retrieval:** a three-signal scoring function — recency (exponential decay
  on timestamps), importance (an LLM-assigned integer), and relevance (cosine
  similarity of embeddings) — combined to fetch the top-scored records
  (Generative Agents, §3; corroborated by CoALA, §4.3).
- **Effect:** ablations show observation/planning/reflection each contribute
  significantly to coherent long-horizon behavior (Generative Agents, abstract).

### A-Mem — Zettelkasten note graph; Mem0 — extracted fact store

- **A-Mem stored/retrieved:** on each new memory, "construct structured memory
  notes that capture both explicit information and LLM-generated contextual
  understanding," then "analyzes the historical memory repository to establish
  meaningful connections based on semantic similarities," producing an
  "interconnected knowledge network" that self-evolves without
  predetermined write points (Xu, Liang, Mei, Gao, Tan & Zhang, "A-Mem: Agentic
  Memory for LLM Agents," *NeurIPS* 2025, arXiv:2502.12110, abstract, §3).
  Reports both token savings and performance gains over static-structured
  baselines (A-Mem, §5).
- **Self-notes (the working-memory variant):** a model trained to interleave
  "Self-Notes" with the input "can use notes as a form of working memory …
  write the latest state of an entity as new" facts are inferred (Wang &
  Anadkat, "Learning to Reason and Memorize with Self-Notes," arXiv:2305.00833,
  §1, §5).
- **Mem0 stored/retrieved/effect:** "dynamically extracting, consolidating,
  and retrieving salient information from ongoing conversations"; on LOCOMO it
  reports "26% relative improvements in the LLM-as-a-Judge metric over OpenAI"
  and ~91% lower p95 latency vs. full-context (Chhikara et al., "Mem0: Building
  Production-Ready AI Companions with Advanced Memory Management,"
  arXiv:2504.19413, abstract).

## 3. Memory failure modes

The record is unambiguous that memory is a *load-bearing* component that can
net *hurt* once it grows, goes stale, or gets poisoned.

### Retrieval pollution and the memory that hurts

- **Continuously rewritten consolidated memory degrades non-monotonically and
  can fall below no-memory.** "As consolidation proceeds, memory utility first
  rises, then degrades, and can fall below the no-memory baseline. More
  surprisingly, even when consolidating from ground-truth solutions, GPT-5
  fails on 54% of a set of ARC-AGI problems it had previously solved without
  memory." Cause is attributed to the iterative update process itself: "the
  same trajectories yield qualitatively different memories under different
  update schedules, while an episodic-only control over those trajectories"
  retained utility (Zhang et al., "Useful Memories Become Faulty When
  Continuously Updated by LLMs," *NeurIPS* 2026 workshop / arXiv:2605.12978,
  abstract, §4.1). This is the single most cautionary result for a learn-once
  layer: **write-once is only safe if the written abstraction stays
  faithful; continuous re-abstraction corrupts it.**
- **Memory agents repeatedly reuse now-invalid memories.** A benchmark that
  "penalizes reliance on obsolete or invalidated memory" finds "frequent reuse
  of invalid memories," and that "even agents with explicit memory stores
  become increasingly brittle as memory grows longer and more mutation-heavy,"
  with week-to-quarter degradation across 4 LLMs and 6 memory agents ("From
  Recall to Forgetting: Benchmarking Long-Term Memory for Personalized
  Agents," arXiv:2604.20006, abstract, §4).
- **A recall-vs-utilization gap.** Systems "performing strongly on factual
  memory benchmarks degrade substantially when tasks require cross-session
  reasoning," including against semantically similar distractors: "strong
  performance on conventional factual-memory benchmarks does not reliably"
  transfer ("UtilMem: Benchmarking Evidence Utilization in Long-Term
  Conversational Memory," arXiv:2608.30508, abstract).
- **Commercial assistants already show a 30% accuracy drop** on long-term
  memorization across sustained interactions, and LongMemEval declares five
  required abilities, two of which are explicitly failure-aware: *knowledge
  updates* and *abstention* (knowing not to answer from stale memory) (Wu et
  al., "LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive
  Memory," arXiv:2410.10813, abstract).
- **Benchmarked across four competencies.** MemoryAgentBench identifies
  accurate retrieval, test-time learning, long-range understanding, and
  *selective forgetting* as the core competencies, flagging forgetting as
  under-evaluated (2707.05257 — "Evaluating Memory in LLM Agents via
  Incremental Multi-Turn Interactions," arXiv:2507.05257).
- **Retrieval signal dominates write strategy — where the hurt concentrates.**
  A 3×3 study crossing write strategies (raw chunks / Mem0-style fact
  extraction / MemGPT-style summarization) with retrieval methods (cosine,
  BM25, hybrid rerank) finds "average accuracy spans 20 points across retrieval
  methods … but only 3–8 points across write strategies" on LoCoMo
  ("Diagnosing Retrieval vs. Utilization Bottlenecks in LLM Agent Memory,"
  ICLR 2026, https://iclr.cc/virtual/2026/10021251). A prior survey makes the
  same point in one line: "The bottleneck shifts decisively from storage to
  *relevance*: ensuring that the most *useful*—not merely the most
  *similar*—records are returned" (arXiv:2603.07670, §2).

### Poisoning: the memory store is a trust boundary

- **AgentPoison** backdoors RAG/agent memory by injecting crafted
  demonstrations: "achieves an average attack success rate higher than 80% with
  minimal impact on benign performance (less than 1%) with a poison rate less
  than 0.1%," demonstrated on an RAG autonomous-driving agent, a
  knowledge-intensive QA agent, and a healthcare agent (Chen et al.,
  "AgentPoison: Red-teaming LLM Agents via Poisoning Memory or Knowledge
  Bases," *NeurIPS* 2024, arXiv:2407.12784).
- **Query-only injection.** MINJA poisons the memory bank "by only interacting
  with the agent via queries and output observations," deliberately exploiting
  that "records in the memory bank serve as in-context demonstrations of LLM
  agents during inference" (Dong et al., "Memory Injection Attacks on LLM
  Agents via Query-Only Interaction," *NeurIPS* 2025,
  https://proceedings.neurips.cc/paper_files/paper/2025/hash/42a97bbd9844d2bf68596730af80bcdf-Abstract-Conference.html).
- **MemoryGraft** argues experience-reuse systems create "a critical,
  unexplored attack surface, i.e., the trust boundary" of experience
  retrieval: poisoned recalled experiences produce "durable, trigger-free
  behavioral drift" (Srivastava et al., "MemoryGraft: Persistent Compromise of
  LLM Agents via Poisoned Experience Retrieval," arXiv:2512.16962).
- **Implication:** every memory record is a *demonstration* that steers future
  behavior; a recall layer that replays unvetted lessons replays the whole
  poisoning surface.

### Mitigations that appear in the literature and in shipped systems

- **Vote/importance counts that delete on disagreement** — ExpeL's
  upvote/downvote that removes an insight at zero importance (§2 above).
- **Update-in-place and delete primitives** — Mem0's `update`/`delete`
  operations "when a new [fact] contradicts" an old one; and its "immutable"
  flag for memories that may never be silently updated (Mem0 docs, "How Mem0
  Works" and "Delete Memory Operation,"
  https://docs.mem0.ai/core-concepts/how-it-works,
  https://docs.mem0.ai/core-concepts/memory-operations/delete).
- **Provenance + abstention** — "Agent Zero Memory" distills provenance "of
  everything a user or organization has said and stored" and, when provenance
  can't support an answer, "the system abstains rather than guesses," reaching
  95.60% LongMemEval and 93.60% LoCoMo ("Agent Zero Memory: Provenance-Aware
  Long-Term Memory for LLM Agents," arXiv:2608.29606, abstract).
- **Anti-rot scrub on the instruction/memory files themselves** — Claude Code's
  `/doctor prompt-audit` checks "for outdated or conflicting content …
  references to files or commands that don't exist, and files that contradict
  each other" (Claude Code docs, "How Claude remembers your project,"
  https://code.claude.com/docs/en/memory#audit-your-instruction-files).

## 4. De-duplication and learn-once

Directly on the question "how do we detect that a lesson is already known, so
we don't capture it again?"

- **Dedup is an explicit write-stage step in shipped memory systems.** Mem0's
  write pipeline is three stages: "Context lookup: Mem0 checks related existing
  memories so it can avoid storing the same fact again," then "Fact
  extraction," then "Deduplication and embedding: Redundant facts are removed"
  (Mem0 docs, "How Mem0 Works"). So learn-once = check-before-write against the
  existing store, then store only the *new* delta.
- **Novelty-gated write control beats both "always append" and "always ask the
  LLM."** SAGE frames "memory evolution as a novelty-detection problem":
  "resolves clearly novel facts as ADD, clearly redundant facts as NOOP, and
  sends only uncertain cases to an LLM merge step, reducing expensive
  write-time reasoning" — 3.4× cheaper add-phase API calls on LoCoMo while
  matching Mem0's token-F1, and dropping ~16–18% of LLM calls when used as a
  gate on A-Mem (Wang et al., "SAGE: A Novelty Gate for Efficient Memory
  Evolution in Agentic LLMs," arXiv:2605.30711, abstract). The paper's diagnosis
  is the learn-once rationale in almost our words: "a memory that is never
  written cannot be retrieved, and a memory that is written incorrectly
  (duplicated, merged with an un-related fact, or prematurely deleted) will
  degrade downstream queries that touch it."
- **Mem0's controller is an ADD / UPDATE / DELETE / NOOP decision** — the
  LLM-mediated write controller that SAGE benchmarks against (per SAGE's
  related-work section; Mem0's `add`/`update`/`delete` primitives at
  https://docs.mem0.ai/core-concepts/memory-types).
- **Voyager learns once *by construction* — a skill is stored only if it is new
  and only if it works.** Skills are committed only after passing
  self-verification, and the retrieval step reuses existing skills rather than
  re-deriving them, which is precisely why the library transfers to a clean
  world (Voyager, §3; arXiv:2305.16291). Reuse-on-retrieval is the environment
  side of learn-once.
- **Consolidation should be conservative and traceable back to episodes.** The
  degradation result's control condition is the telling mitigation: "an
  episodic-only control over those trajectories" avoided the collapse that
  continual re-abstraction suffered — i.e., keep the raw lesson (what happened)
  and let the abstraction (what to do next time) be *derivable from* it, not
  endlessly rewritten over it (Zhang et al., arXiv:2605.12978, §4.1).
- **Claude Code's auto-memory writes with explicit skip rules** that are a live
  dedup policy: "Claude skips anything it can derive from the codebase … It
  also skips anything your CLAUDE.md files already say. Claude doesn't save
  something every session. It decides what's worth remembering based on whether
  the information would be useful in a future conversation" (Claude Code docs,
  "How Claude remembers your project,"
  https://code.claude.com/docs/en/memory#auto-memory). Write-once is enforced by
  *not writing what's already derivable or already recorded*.
- **The write side is the under-invested half.** "prior work has focused more
  on retrieval and storage than on principled write-side control" (SAGE,
  abstract); and CoALA listed *updating retrieval* and *unlearning* as open
  problems (§4.5) — a learn-once layer is, as a research matter, mostly
  unexplored territory with only SAGE/Mem0 as direct precedent.

## 5. Human-in-the-loop memory and provenance

The authorized-vs-automatic split we called "the Claude/Codex distinction" is
both a shipped industry pattern and, at the scholarly level, a
provenance/trust-boundary argument.

- **Claude Code separates human-written rules from Claude-written memories.**
  Two complementary systems: CLAUDE.md ("instructions you write … instructions
  and rules") vs. auto memory ("notes Claude writes itself based on your
  corrections and preferences … learnings and patterns") — "Use CLAUDE.md
  files when you want to guide Claude's behavior. Auto memory lets Claude learn
  from your corrections without manual effort" (Claude Code docs, "How Claude
  remembers your project,"
  https://code.claude.com/docs/en/memory#claudemd-vs-auto-memory). The write
  trigger for the human store is *repetition*, not agency: add to CLAUDE.md
  "when Claude makes the same mistake a second time" (same page).
- **Claude's memory tool is client-side and user-visible.** "Claude only
  requests memory operations" and the application executes them locally, "gives
  you complete control over where and how the memory is stored," restricted to
  a designated `/memories` directory (Anthropic, "Memory tool,"
  https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/memory-tool).
  The consumer product states the same stance: memory is "fully optional, with
  granular user controls that help you manage what Claude remembers" (Anthropic
  news, "Bringing memory to teams,"
  https://www.anthropic.com/news/memory).
- **Codex states the canonical/recall separation as a hard rule.** "**Keep
  required team guidance in AGENTS.md or checked-in documentation. Treat
  memories as a helpful recall layer, not as the only source for rules that
  must always apply.**" — and the memory files are "generated state … don't rely
  on editing them by hand" (OpenAI, "Codex Memories,"
  https://developers.openai.com/codex/customization/memories). This is the
  cleanest first-party articulation of exactly the split a recall layer
  needs: *authorized, always-apply* guidance versus *automatic, advisory* recall.
- **Codex memories are background-written and gated on eligibility**, not
  end-of-chat: "Codex skips active or short-lived sessions, redacts secrets
  from generated memory fields, and updates memories in the background instead
  of immediately at the end of every chat" (same page, "How local Codex
  memories work"). Two design levers a learn-once layer can copy: *deferring*
  capture until a session is settled, and *redacting* secrets before persistence.
- **The scholarly counterpart is provenance-gated memory with abstention.**
  Agent Zero Memory argues most memory systems "commit to a single organizing
  structure … and inherit its blind spots," and instead distills a
  provenance-aware store where unsupported answers abstain rather than guess
  (arXiv:2608.29606, abstract) — provenance as the mechanism that decides
  whether a recalled lesson may be *acted on*.
- **The risk that motivates the split is procedural-memory subversion.** CoALA
  justifies treating self-written procedures as riskier than self-written
  facts (arXiv:2309.02427, §4.1, §4.5), and the poisoning literature shows the
  mirror-image risk in the *read* direction: recalled records "serve as
  in-context demonstrations" that steer behavior (MINJA, NeurIPS 2025), and
  experience retrieval is "the trust boundary" of self-improving agents
  (MemoryGraft, arXiv:2512.16962). Human-authorized memories are the
  high-assurance tier; auto memories are the advisory tier — the split is not
  aesthetic, it is a trust-boundary placement.

## 6. Design guidance for a learn-once recall layer

Numbered principles, each grounded in a cited result.

1. **Structure the recall layer as CoALA-style semantic memory with a bounded
   working set, not as an ever-growing prompt.** Store lessons as semantic
   facts/insights retrieved into working memory on demand; keep working memory
   a persistable data structure across calls, not the LLM's raw context
   (CoALA §4.1, arXiv:2309.02427).
2. **Retrieve by usefulness, not just similarity.** Performance differences
   concentrate in the retriever (20-point spread across retrieval methods vs.
   3–8 across write strategies), and the survey's verdict is "the most
   *useful*—not merely the most *similar*—records"; combine recency +
   importance + relevance as Generative Agents does (ICLR 2026 diagnostic,
   arXiv:2603.07670, arXiv:2304.03442).
3. **Write once, gated by novelty: check-before-write, dedup, and prefer NOOP /
   merge over ADD.** Mem0's context-lookup-before-store and SAGE's ADD /
   NOOP / merge gate are the only published learn-once write policies, and SAGE
   shows the gate *saves* cost and tokens while holding quality
   (https://docs.mem0.ai/core-concepts/how-it-works, arXiv:2605.30711).
4. **Keep the episode alongside the lesson, and abstain rather than replay a
   stale lesson.** Continuous re-abstraction corrupts memory below the
   no-memory baseline while an episodic-only control stayed useful — so treat
   lessons as *derived artifacts* that must remain tractable to their source
   episode, and gate recall on provenance/abstention (arXiv:2605.12978,
   arXiv:2608.29606, arXiv:2410.10813).
5. **Make the write/read loop tri-state, not append-only: the manage step must
   summarize, deduplicate, resolve contradictions, and delete.** This is the
   survey's prescription for `U` in the write–manage–read loop
   (arXiv:2603.07670, §2), and ExpeL's upvote/downvote-to-deletion and Mem0's
   update-in-place are concrete instantiations (arXiv:2308.10144, Mem0 docs).
6. **Separate the human-authorized tier from the agent-ephemeral tier, and
   keep the authorized tier the only "always-applies" store.** Codex's explicit
   rule ("Treat memories as a helpful recall layer, not as the only source for
   rules that must always apply") and Claude Code's CLAUDE.md-vs-auto-memory
   split are the shipped pattern; CoALA's warning that self-written procedures
   are the riskiest writes generalizes it (Codex/Claude docs cited §5,
   arXiv:2309.02427).
7. **Treat the store as a trust boundary, because recalled records are
   demonstrations.** A <0.1% poison rate already yields >80% attack success
   (AgentPoison), and query-only interaction suffices to inject records (MINJA)
   — so auto-admitted lessons need provenance, scoping, and ideally
   authorization before they become load-bearing (arXiv:2407.12784, NeurIPS
   2025, arXiv:2512.16962).
8. **Learn-once is earned by re-use, not by capture: prefer the reusable
   artifact.** Voyager's verified skill library is the model to follow — a
   lesson is stored only if it *works*, and it pays off in a clean world
   because it is retrieved and composed rather than re-derived
   (arXiv:2305.16291). Cross-task transfer additionally requires abstracting
   across instances (ExpeL) rather than per-task self-talk (Reflexion).
9. **Defer capture and scrub the lessons file.** Background-written, gated-on-
   settled-state capture with secret redaction (Codex memories), and a
   dedicated audit for "outdated or conflicting content" (Claude Code
   `/doctor prompt-audit`), are the two shipped anti-rot mechanisms a recall
   layer should have from day one (docs cited §5).

### Most decision-relevant findings

1. **Self-rewritten memory is not monotonic good — it can fall below
   no-memory.** "Useful Memories Become Faulty" (arXiv:2605.12978) shows
   consolidated lessons degrade with each update, sometimes worse than no
   memory at all, and that an episodic-only control avoids the collapse. This
   is the strongest published caution against an *automatically self-updating*
   lesson store.
2. **The retriever, not the writer, decides whether memory helps.** A 20-point
   accuracy spread across retrieval methods vs. 3–8 across write strategies
   (ICLR 2026 diagnostic); the bottleneck "shifts decisively from storage to
   relevance" (arXiv:2603.07670). Invest in recall *selection* first.
3. **Check-before-write is both cheaper and safer.** SAGE's novelty gate
   (ADD/NOOP/merge) cuts write-phase cost 3.4× while matching quality; Mem0
   ships context-lookup-before-fact-store as its dedup step. Learn-once has a
   direct, published mechanism.
4. **The memory store is a demonstration surface, hence a trust boundary.**
   AgentPoison hits >80% attack success at <0.1% poison rate, and MINJA does it
   through query-only interaction — recalled lessons actively steer behavior,
   so unvetted auto-memory is a live attack surface.
5. **The authorized-vs-automatic split is real, shipped, and principled.**
   Codex ("treat memories as a helpful recall layer, not the only source for
   rules that must always apply") and Claude Code (CLAUDE.md vs. auto memory)
   both separate human-authorized guidance from agent-written recall; the
   scholarly counterpart is provenance-gated memory with abstention
   (arXiv:2608.29606).
